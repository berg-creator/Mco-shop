# Mco shop — правила проекта

Магазин одежды в Telegram: бот принимает заказы, мини-приложение показывает
наличие. Проект-сосед — канал [Mco mag](../Mco-mag), но код общий не ведётся:
у канала GitHub Actions без сервера, здесь — постоянно работающий процесс.

Этот файл — только правила и карта. «Почему так» живёт в докстринге модуля,
которого касается правка: длинные разборы решений оттуда сюда не переносятся,
иначе каждый разговор начинается с чтения всей истории проекта.

## Язык

**Общение с владельцем проекта — только по-русски.** Это касается и ответов
в чате: объяснения, отчёты о сделанном, вопросы — всё по-русски, без перехода
на английский даже в технических пояснениях.

Русский везде, где текст читает человек: докстринги, комментарии, коммиты,
README, тексты бота и витрины. **Имена в коде — английские**, как у канала
в `/Users/mke/MUZ AI`: два соседних проекта должны выглядеть родными.

## Архитектура и почему так

- **Один процесс на всё** (`src/app.py`): бот (long polling) и HTTP-сервер
  поднимаются вместе. Для сотни заказов в месяц разделять их — лишние
  движущиеся части.
- **Long polling, а не webhook**: работает без белого IP и сертификата, значит
  один и тот же код идёт и на маке через туннель, и на VPS.
- **SQLite, а не JSON-файлы**: пишут одновременно покупатели и админка, нужны
  транзакции — последнюю куртку нельзя продать дважды.
- **Остаток и резерв — разные вещи.** Заказ резервирует, подтверждение
  списывает, отказ снимает резерв. Заявка без ответа за 72 часа становится
  `expired`, и вещь возвращается в витрину; чистка вызывается из `db.catalog()`,
  на открытии витрины, — ни таймера, ни фоновой задачи.
- **Фото — файлами** в `data/photos/`, в базе только имена: витрина отдаёт их
  статикой, а не гоняет `file_id` через Bot API на каждый показ.
- **Музыка — в `data/music/`, а не в `webapp/`**: выкладка затирает `webapp/`
  целиком, и присланные владельцем песни уезжали бы при каждом деплое. Темп
  меряется один раз, при загрузке, и приезжает в витрину вместе с каталогом.
  Плейлист (`tracks.json`) отдаётся списком, порядок тасует витрина. Своей
  музыки нет — в витрине тихо, трека по умолчанию в `webapp/` не лежит.
  Как меряется темп и почему периодом, а не складкой — докстринг `src/music.py`.
- **Связь с продавцом — пересылка, а не своя переписка.** Написанное боту
  пересылается владельцу, ответ на пересылку бот копирует покупателю. Ни
  таблицы диалогов, ни чата в витрине: Telegram уже хранит и автора,
  и историю. Кнопка в витрине открывает личку владельца (`SELLER` в
  `webapp/app.js`).
- **Каждый запрос из Mini App проверяется по подписи** `initData` (HMAC-SHA256
  на ключе из токена бота). Без этого любой пришлёт заказ от чужого имени.

## Стиль

- Докстринг модуля объясняет решение: чем модуль занят, почему сделан так,
  какая альтернатива отвергнута. Комментарии в коде — про «почему», а не «что».
  Разбор решения дописывается туда, а не в этот файл.
- У модулей есть «сухие» режимы (`--check`, `--dry-run`), которые ничего
  не пишут.
- Зависимостей минимум: `aiogram` (бот) и `aiohttp` (приезжает с ним). Каждая
  новая — отдельное решение. `coverage` и `fonttools` — только для разработки.
- Сообщения коммитов по-русски, обычной фразой о смысле изменения.
- Деньги — целые рубли в `INTEGER`: копейки не нужны, а float на деньгах
  когда-нибудь ошибётся.

## Из чего собрано

- [src/app.py](src/app.py) — точка входа, поднимает бота и веб в одном цикле.
- [src/server.py](src/server.py) — HTTP: витрина, `/api/catalog`, `/api/order`,
  проверка подписи `initData`.
- [src/bot.py](src/bot.py) — вход в витрину, заявки и вопросы покупателей.
- [src/admin.py](src/admin.py) — добавление товара и остатки с телефона.
- [src/db.py](src/db.py) — вся работа с SQLite, резерв и списание.
- [src/music.py](src/music.py) — плейлист витрины, темп песен и ритм листания.
- [src/scrape.py](src/scrape.py) — сбор каталога из публичного канала.
- [src/importer.py](src/importer.py) — разбор экспорта канала и заливка черновиков.
- [webapp/](webapp/) — витрина: ванильный JS без сборщика. Знак, планета,
  заставка, музыка на экране и логотипы марок разобраны
  в [webapp/README.md](webapp/README.md) — читать, когда правишь витрину.
- [tools/](tools/) — генераторы `webapp/wordmark.js` и `webapp/land.js`; нужны
  только при смене имени, шрифта или карты, работают на маке.
- [scripts/deploy.sh](scripts/deploy.sh) — разворот и выкладка на VPS, а в нём
  сторож `shop-watch`: раз в час смотрит на то, что ломается тихо, и сначала
  пробует вылечить сам. Появился новый тихий отказ — учи сторожа его замечать,
  это часть правки, а не отдельная задача.
- [run.sh](run.sh) — запуск для теста: туннель, адрес витрины в `.env`, магазин.
  Туннель через pinggy по ssh на 443 — `cloudflared` просит порт 7844, а он
  в домашней сети закрыт, и витрина снаружи отдаёт ошибку 1033.

## Команды

```bash
./run.sh                           # туннель + магазин: свежий адрес витрины сам
python -m src.db --init --demo     # база и демо-товары для проверки витрины
python -m src.app                  # бот и витрина
python -m src.app --web-only       # только витрина, без токена (отладка)
python -m src.app --check          # проверить конфиг и базу, ничего не запуская
python -m src.db --check           # что лежит в каталоге
python -m unittest discover tests  # весь бот: 241 тест
python -m coverage run -m unittest discover tests && python -m coverage report -m
python -m src.scrape <канал> --out draft.json     # каталог из публичного канала
python -m src.importer --apply draft.json         # залить черновик в базу
python -m src.music song.mp3                      # какой темп в файле
python -m src.music --add альбом/*.mp3            # песни в плейлист витрины
python3 tools/wordmark.py "M co."                 # контуры имени для заставки
python3 tools/globe.py                            # берега материков для планеты
```

Каталог всегда заливается в два шага — сначала черновик JSON, потом `--apply`.
Разбор постов эвристический, а в витрине окажутся цены, по которым придётся
продавать: между машиной и покупателем должен быть человек, посмотревший глазами.

## Тесты

Покрывают `src/` целиком — каждую строку и каждую ветку, планка 100% записана
в `.coveragerc`. Смысловое ядро — то, что стоит денег: двойная продажа (в том
числе двумя строками в одной заявке), возврат резерва, подделка подписи, разбор
цены из поста, приём заявки живым сервером и экранирование чужого текста в HTML.

Раскладка: `test_shop.py` — остатки, подпись, веб-API; `test_music.py` — темп
на дорожке с известным битом, плейлист и жизнь без ffmpeg; `test_bot.py`
и `test_admin.py` — обработчики и мастер добавления товара на заглушках
из `tests/fakes.py`; `test_cli.py` — настройки, запуск, командная строка базы;
`test_catalog.py` — сбор каталога из канала и экспорта. Telegram и сеть
не трогаются: `urlopen` подменяется, Bot API заменён заглушкой.

Витрина проверяется глазами — `--web-only` и браузер: это DOM-код, и его тесты
потребовали бы node с jsdom, то есть ещё одну инфраструктуру ради слоя, где
ошибка видна с первого взгляда.
